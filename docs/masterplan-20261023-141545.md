## 1. Executive Summary

This masterplan specifies the architectural overhaul of the Matrix-FSM output and state-completion system. It eliminates syntax fragmentation (`emit` vs. `output` vs. `finalState`), restores the visual table alignment of the 4-column transition matrix, and establishes a single, cohesive, type-safe API for all outputs (terminal and non-terminal).

### Core Breakthroughs:
1. **The 4-Column Contract Restored:** Column 3 (`TO`) is strictly restricted to compact destination markers (`finalState()`, `stay()`, `'stateName'`, `awaiting('stateName')`). All context projections, lambdas, and payload selectors are moved to Column 4 (`OPTIONS`).
2. **Complete Elimination of `emit`:** The term `emit` is removed from the codebase. All communication to the parent machine uses `output`.
3. **Universal 2-Element Tuple Syntax:** Non-void outputs uniformly use `output: ['EVENT_NAME', (ctx, eventPayload) => payloadSelector]` across terminal completions, intermediate stream ticks, and regular state changes.
4. **Deterministic Execution Order:** Synchronous mutations (`patch` / `call`) execute first, followed by the `output` selector with fresh state, followed by parent event dispatch.
5. **Zero Magic / No Unnamed Payloads:** Implicit `finalState()` defaults to `'DONE'` with `void` payload. Emitting data strictly mandates specifying the output event name.

## 2. Settled Decisions & Rationale (Design Tree)

| Question | Topic | Decision | Architectural Rationale |
| :--- | :--- | :--- | :--- |
| **Q1** | **Child Lifecycle vs. Output** | **A: Sub-Actor Lifecycle Determines Teardown** | Keeps a unified `outputs` map in the machine contract. The child transition target (`finalState` vs. `stay`/state) dictates whether the child actor terminates or remains active. If the parent transitions away on an intermediate output, the parent's standard state-exit automatically aborts/kills the child actor. |
| **Q2** | **Selector Arguments** | **A: Dual Signature `(ctx, eventPayload)`** | Allows output payloads to consume both the updated machine state (`ctx`) and the triggering event payload (`eventPayload`, e.g. raw sensor/timer data or task resolve value) without forcing intermediate context patches. |
| **Q3** | **`void` Output Shorthands** | **A: Flexible String or 1-Tuple + Collision Guard** | For void outputs, both `output: 'HEARTBEAT'` and `output: ['HEARTBEAT']` are valid. If `finalState('CANCELLED')` is used in Column 3, Column 4 strictly forbids `output` (`output?: never`). |
| **Q4** | **Legacy Migration** | **A: Hard Cut (Breaking Change)** | Immediate removal of `emit` and the 2nd parameter from `finalState(name, selector)`. Codebase, tests, and playground are updated in one atomic pass, preventing legacy debt. |
| **Q5** | **Output Cardinality** | **A: Strictly At Most 1 Output Per Row** | Enforces KISS and determinism. Multiple simultaneous outputs must be modeled as separate transitions or bundled into a domain event object. |

## 3. Technical Specifications

### 3.1 Package: `@matrix-fsm/core`

#### File: `packages/core/src/lib/primitives.ts`
1. **Modify `finalState` Signatures:**
   Remove the optional `payloadSelector` parameter. Support only 0-arg and 1-arg calls:
   ```typescript
   export function finalState(): FinalNode<'DONE'>;
   export function finalState<const TOutcome extends string>(
     outcome: TOutcome
   ): FinalNode<TOutcome>;
   export function finalState(outcome?: string): FinalNode<string> {
     return Object.freeze({
       __type: 'finalState' as const,
       outcome: outcome ?? 'DONE',
     });
   }
   ```
2. **Update Node Definitions:**
   Update `FinalNode<TOutcome>` in `types.ts` to drop `payloadSelector`.

#### File: `packages/core/src/lib/types.ts`
1. **Define Output Tuple Types:**
   ```typescript
   export type TransitionOutputTuple<TOutputs, TContext, TPayload> = {
     [K in keyof TOutputs]: TOutputs[K] extends void
       ? K | readonly [K]
       : readonly [
           K,
           (ctx: ReadonlyContext<TContext>, eventPayload: TPayload) => TOutputs[K]
         ];
   }[keyof TOutputs];
   ```
2. **Update `TransitionOptions`:**
   - Remove `readonly emit?: ...`
   - Add `readonly output?: TransitionOutputTuple<TOutputs, TContext, TPayload>;`
3. **Collision Guard on Column 3 / Column 4:**
   When Column 3 (`TO`) is `FinalNode<TOutcome>` where `TOutcome !== 'DONE'`:
   - If `TOutputs[TOutcome]` is `void`, `finalState(TOutcome)` is permitted without Column 4 `output`.
   - In this row, `options.output` is constrained to `never` to prevent dual-declaration.
   - When Column 3 is `finalState()` (default `'DONE'`), `options.output` is required if an output with payload is being emitted.
4. **Compile-Time Exhaustiveness (`ValidateSubMachineOutputs`):**
   Ensure `ValidateSubMachineOutputs` scans both explicit `FinalNode<TName>` targets and `options.output` definitions in the child matrix against parent transitions.

#### File: `packages/core/src/lib/fsm.ts`
1. **Update Transition Evaluation Logic:**
   - Remove legacy `options.emit` processing.
   - Parse `options.output`:
     - If string: `{ type: options.output, payload: undefined }`
     - If 1-tuple `[type]`: `{ type: options.output[0], payload: undefined }`
     - If 2-tuple `[type, selector]`: evaluate `selector(nextContext, payload)`
   - Set `emittedOutput` on the transition result.
2. **Execution Order Guarantee:**
   ```typescript
   // 1. Calculate next context via patch
   const patchApplied = options?.patch ? options.patch(currentContext, payload) : null;
   const nextContext = patchApplied ? { ...currentContext, ...patchApplied } : currentContext;

   // 2. Evaluate output selector using updated context
   let emittedOutput = null;
   if (options?.output) {
     if (typeof options.output === 'string') {
       emittedOutput = { type: options.output, payload: undefined };
     } else if (Array.isArray(options.output)) {
       const [type, selector] = options.output;
       emittedOutput = {
         type: String(type),
         payload: typeof selector === 'function' ? selector(nextContext, payload) : undefined,
       };
     }
   }
   ```

#### File: `packages/core/src/lib/runner.ts`
- Preserve the existing dual-dispatch logic:
  - If `childInfo.emittedOutput`: dispatch to parent `send(outType, outPayload)`. Sub-actor remains running.
  - If `childInfo.isDone`: determine final outcome name (from `options.output` if present, else `finalOutcome` string). Tear down child actor, then dispatch to parent `send(outcome, payload)`.

### 3.2 Package: `@matrix-fsm/angular`

#### File: `packages/angular/src/lib/with-state-machine.ts`
1. **Child Actor Teardown vs. Continuation:**
   - Intermediate outputs (from `stay()` or non-final states) trigger `onEmitOutput` without calling `destroyActiveSubNode()`.
   - Terminal outputs (`finalState()`) call `destroyActiveSubNode()` and dispatch completion event to parent.
2. **Parent Reaction Handling:**
   - If parent transition for sub-machine event is `stay()`, child stays alive.
   - If parent transition exits the sub-machine state, child actor is aborted via its `AbortController`.

## 4. Test Matrix & Validation Plan

### 4.1 Unit Tests (`packages/core/src/lib/core.spec.ts`)
1. **Terminal Output with Payload:** `finalState()` + `output: ['COFFEE_READY', (ctx) => payload]`. Verifies parent receives payload and child is terminated.
2. **Terminal Output without Payload:** `finalState('CANCELLED')` with no `options.output`. Verifies parent receives event and child is terminated.
3. **Intermediate Output with `stay()`:** `stay()` + `output: ['PROGRESS', (ctx) => ({ percent })]`. Verifies parent receives progress and child stays active.
4. **Intermediate Output with State Change:** Transition to `'cleaning'` + `output: ['CLEAN_ALERT']`. Verifies child changes state and parent receives output.
5. **Dual Selector Signature:** Test `output: ['EVENT', (ctx, eventPayload) => ({ combined: ctx.val + eventPayload.val })]`.
6. **Compile-Time Error Tests:**
   - `@ts-expect-error` when `options.output` name is not in `TOutputs`.
   - `@ts-expect-error` when selector return type does not match `TOutputs[K]`.
   - `@ts-expect-error` when `finalState('CANCELLED')` is combined with `options.output`.

### 4.2 Integration Tests (`packages/angular/src/lib/with-state-machine.spec.ts`)
1. Verify reactive signals (`store.actors.<id>()`) update during intermediate outputs.
2. Verify hard kill on parent transition away from sub-machine during intermediate output.
3. Full lifecycle test in `playground.spec.ts` matching the Coffee Shop demo.
