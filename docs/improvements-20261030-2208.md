2. **`void` Output Shorthands:**

   - Bare `finalState()` with no `options.output` implicitly emits `'DONE'` (with `undefined` payload).

## Cycle 8: Mathematical Graph Conservation & Sub-Actor Finalization Safety

### Warum?

1. **In-Degree $\deg^-(v) \ge 1$ (`no-unreachable-states`):** Jeder Knoten in Spalte 1 (`FROM`, außer `anyState()`) muss entweder `initial` sein oder mindestens einmal in Spalte 3 (`TO`, inkl. lokaler `transitions([...])`-Spreads) als Ziel vorkommen.
2. **Transient Out-Degree $\deg^+_{\text{exit}}(v) \ge 1$ (`require-exit-for-targets`):** Jedes in Spalte 3 (`TO`) betretene **transiente Ziel** (`awaiting('...')`, Sub-Akteure wie `baristaFSM`, Kombinatoren wie `all()`, `race()`, `any()`, `each()`) muss mindestens eine explizite Zeile in Spalte 1 (`FROM`) besitzen, die diesen Knoten **wirklich verlässt** (`TO !== stay()` UND `TO !== FROM`, also keine reine Selbstschleife!).
   - _Wichtig:_ Normale String-States (wie `'loggedIn'` oder `'coffeeReady'`) dürfen als Ruhe-/Endzustände ohne ausgehende Transition am Ende eines Flows stehen! Ebenso ersetzt ein globales `[anyState(), ...]` niemals den Pflicht-Ausgang eines transienten Ziels.
3. **Finalization Safety (`ExtractTerminalOutputs<TSub>`):** Terminiert ein Sub-Actor über `finalState()`, ist seine Instanz beendet. Der Parent muss alle Terminal-Outputs (inkl. implizitem `'DONE'` bei `finalState()` ohne `output`) abfangen und darf in keiner dieser Zeilen (auch nicht im Guard-Fallback!) `stay()` als Ziel in Spalte 3 nutzen.

### 🔴 Step 1 (RED): Failing Tests in `core.spec.ts` & `eslint-plugin.spec.ts`

1. **Compile-Time Type Tests (`packages/core/src/lib/core.spec.ts`):**
   - **Test 8a (Unhandled Implicit `'DONE'` from `finalState()`):** Ein Sub-Actor nutzt `['working', 'FINISH', finalState()]` (ohne `output`). Fehlt `[subFSM, 'DONE', ...]` im Parent -> Compile-Error (`// @ts-expect-error`)!
   - **Test 8b (Illegal `stay()` on Terminal Output — Direct & Fallback):** In `baristaFSM` stammt `'COFFEE_READY'` aus einer `finalState()`-Zeile, `'PROGRESS'` aus einer `stay()`-Zeile:
     - `[baristaFSM, 'PROGRESS', stay()]` -> Kompiliert!
     - `[baristaFSM, 'COFFEE_READY', stay()]` -> Compile-Error (`// @ts-expect-error`)!
     - `[baristaFSM, 'COFFEE_READY', 'coffeeReady', { guard: () => true }]` gefolgt vom Fallback `[baristaFSM, 'COFFEE_READY', stay()]` -> Compile-Error (`// @ts-expect-error`) auf der `stay()`-Fallback-Zeile!

## Cycle 9: Global Event Handling with `anyState()` (Column 1 Only & Shadowing Protection)

### Warum?

Globale Events (wie Ionic Deep Links, Push Notifications oder globaler Logout) müssen aus jedem Zustand heraus ansteuerbar sein, ohne jede Zeile zu duplizieren:

- `[anyState(), 'VOUCHER_LINK', stay(), { call: (m) => m._saveVoucher }]` (nicht-unterbrechend: laufender `baristaFSM` läuft weiter).
- `[anyState(), 'QUICK_ORDER_LINK', 'awaitingPayment', { call: (m) => m._setDrink }]` (unterbrechend: laufender `baristaFSM` wird automatisch per `AbortSignal` beendet).

### 🔴 Step 1 (RED): Failing Tests in `core.spec.ts` & `eslint-plugin.spec.ts`

1. **Type Test (`core.spec.ts`):** `anyState()` in Spalte 1 (`FROM`) kompiliert; `['idle', 'GO', anyState()]` (in Spalte 3 `TO`) wirft sofort einen Compile-Error (`// @ts-expect-error`).
2. **Runtime Priority & Hard-Kill Test (`core.spec.ts` / `with-state-machine.spec.ts`):**
   - Spezifische Zeile `['idle', 'LINK', 'special']` gewinnt vor `[anyState(), 'LINK', 'general']`.
   - Während `baristaFSM` in `awaiting('brewingCoffee')` läuft:
     - Trifft `[anyState(), 'VOUCHER_LINK', stay()]`, läuft `brewingCoffee` ungestört weiter (`signal.aborted === false`).
     - Trifft `[anyState(), 'QUICK_ORDER_LINK', 'awaitingPayment']`, wird `brewingCoffee` sofort abgebrochen (`signal.aborted === true`) und die Hauptmaschine wechselt nach `'awaitingPayment'`.
3. **ESLint Test (`no-unreachable-transitions` in `eslint-plugin.spec.ts`):**
   - Steht eine unguarded Zeile `[anyState(), 'CANCEL', 'idle']` **oberhalb** von `['brewing', 'CANCEL', 'cleaning']`, meldet `no-unreachable-transitions` einen Fehler (da `anyState()` die spezifische Zeile darunter abschattet!).

### 🟢 Step 2 (GREEN): Implementation

1. Exportiere `anyState(): AnyStateNode` (`{ __kind: 'anyState' }`) aus `@matrix-fsm/core` (nur in `TransitionFrom` erlaubt).
2. Erweitere `runner.ts`: Prüfe bei jedem Event zuerst den aktiven Sub-Actor (Cooperative), dann spezifische `[currentState, event, ...]`-Zeilen, und als Fallback `[anyState(), event, ...]`-Zeilen. Ist bei einem `anyState()`-Treffer `target !== stay()`, führe für aktive Sub-Akteure / `awaiting`-States denselben sauberen Hard-Kill (`onStateExit` + `AbortController.abort()`) aus.

## Cycle 10: Promise-Style Actor Combinators (`all`, `race`, `any`) & Cross-Store Signal Bridge (`whenSignal`)

### Warum?

1. Mehrere Sub-Akteure sollen wie bekannte JS-Promises in Spalte 3 (`TO`) komponiert werden können (`all(baristaFSM, bakeryFSM)`, `race(nfcFSM, qrFSM)`, `any(btPrinterFSM, wifiPrinterFSM)`), während jede einzelne Maschine immer in exakt **einem** State bleibt.
2. Unabhängige globale Stores (wie `NetworkStore` für Online/Offline) sollen über `on: (net = inject(NetworkStore)) => [whenSignal(net.status, { offline: 'NETWORK_LOST', online: 'NETWORK_RESTORED' })]` deklarativ Events in die Matrix einspeisen können.

### 🔴 Step 1 (RED): Failing Tests in `with-state-machine.spec.ts`

1. **`all(actorA, actorB)`:** Startet beide Akteure gleichzeitig; feuert `'ALL_DONE'` erst, wenn beide `finalState()` erreicht haben; bricht bei Parent-`CANCEL` (oder unbehandeltem Fehler eines Akteurs) sofort beide `AbortSignal`s ab.
2. **`race(actorA, actorB)`:** Sobald `actorA` seinen `finalState()` erreicht, wird `actorB` noch in derselben Millisekunde automatisch per `AbortSignal` abgebrochen (`expect(bSignal.aborted).toBe(true)`).
3. **`whenSignal(signal, mapping)`:** Ändert sich `networkStatusSignal` von `'online'` auf `'offline'`, wird automatisch `'NETWORK_LOST'` in die FIFO-Queue der Maschine gesendet.

### 🟢 Step 2 (GREEN): Implementation in `@matrix-fsm/core` & `@matrix-fsm/angular`

1. Implementiere `all(...)`, `race(...)` und `any(...)` in `primitives.ts`, `types.ts`, `runner.ts` und `with-state-machine.ts`.
2. Implementiere `whenSignal(signal, map)` und die `on`-Option in `createMachineFeature` / `withStateMachine` unter Nutzung eines Angular `effect()` (mit `allowSignalWrites: true` bzw. Queue-Dispatch), der beim Store-Destroy automatisch aufgeräumt wird.
